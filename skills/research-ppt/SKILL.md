# Research PPT

연구자가 이미 밝힌 내용과 아직 검증하지 않은 내용을 구분하면서, 처음 보는 청중이 연구의 필요성과 방법을 따라갈 수 있는 발표 자료를 만든다. 이번 사용자의 명시적 지시가 아래 기본값보다 우선한다.

## 적용 범위와 산출물

- 연구 제안, 텀 프로젝트, 연구실 발표, 학위 발표의 신규 작성과 기존 PPT 수정을 다룬다. 읽기·설명만 요청했다면 파일을 수정하지 않는다.
- 요청한 형식의 편집 가능한 발표 자료를 제공한다. PowerPoint/PPTX 요청이면 `.pptx`를 만든다. 대본과 번역은 요청한 경우 함께 제공한다.
- 이 스킬은 연구 내용·발표 흐름·품질 기준을 정한다. 사용 가능한 발표 제작 도구의 공식 사용법을 확인하되, 특정 서비스나 유료 API를 설치·구매하는 것을 전제로 하지 않는다.

## 1. 기존 선택과 수정 범위를 먼저 파악한다

최신 사용자 파일, 확정 제목, 연구 질문, 청중, 발표 시간, 언어, 제출 조건, 선행연구 포함·제외 기준을 확인한다. 사용자 수정본을 작업 기준으로 삼고 이미 승인된 레이아웃·수식·로고를 보존한다. 파일명의 `final`이나 최근 수정 시각만으로 기준 파일을 추정하지 않는다.

필요한 가정이 비어 있다면 독립적으로 진행할 수 있는 작업을 먼저 한다. 연구 대상·목적함수·비용 범위처럼 결론을 바꾸는 결정은 설계 논의를 거친다. 단순 배치나 표현 수정까지 재승인을 요구하지 않는다. 확정 제목이나 연구 범위를 임의로 바꾸지 않는다.

개인 이름·학번·특정 연구 가정은 사용자의 현재 자료에서 가져온다. 이 스킬에 고정된 값은 없다. 대화에서 유래한 기준과 사례별 가정의 구분은 [요구사항의 적용 범위](references/requirements-map.md)를 참고한다.

신규 제안 발표의 기본 흐름은 **표지 → 배경·문제 → 연구 질문·범위 → 선행연구 → 종합 인사이트·한계·기여 → 전체 프레임워크 → 파트별 핵심 모형 → 예상 출력 → References**다. 현재 과제와 합의한 순서가 있으면 그것을 따른다. 일부 페이지 수정 요청을 전체 재구성 요청으로 확대하지 않는다.

## 2. 선행연구로 연구 필요성을 구성한다

문헌 조사·선행연구 표·차별점 작성 시 [선행연구와 논리 구성](references/literature-and-story.md)을 읽는다.

- 연구 목적과 의사결정이 가장 가까운 실증·모형 연구를 중심으로 조사한다. 프레임워크 소개 논문을 응용 연구의 베이스라인으로 대체하지 않는다.
- 논문 원문에서 대상, 선택 대안, 비용, 운영 규칙, 시뮬레이터, 지표와 한계를 확인한다. 공개 코드·데이터·실험 재현 가능성은 별도로 확인한다.
- 짧은 제안 발표의 선행연구는 기본 1–3장, 비교 표는 전체 1–3개로 압축한다. 실제 논문의 문헌 비교 표에서 쓰는 열을 확인하고 현재 질문에 필요한 열을 고른다.
- 각 표 아래에는 그 표의 근거에서 얻는 핵심 메시지를 한 문장으로 쓴다. 그 문장을 곧바로 본 연구의 실행 계획으로 바꾸지 않는다.
- 선행연구 페이지는 선행연구 자체를 설명한다. 다음 종합 페이지에서 **밝혀진 내용 → 남은 한계·미확인 관계 → 본 연구 질문과 기여**를 연결한다.
- 새로움이 의심되면 가까운 통합 연구를 다시 찾는다. 검색되지 않았다는 이유로 “아직 없다”거나 “최초”라고 쓰지 않는다.

## 3. 프레임워크를 만들고 필요한 수식만 설명한다

방법론·수식·예상 결과를 다룰 때 [프레임워크와 수식](references/framework-and-equations.md)을 읽는다.

- 연구 유형에 맞는 전체 프레임워크를 먼저 한 장으로 보여 준다. 실증·실험·이론 연구는 각각 데이터 분석·개입 비교·가정과 논증의 관계를 표현한다. 시뮬레이션·운영 연구는 입력, 의사결정, 선택 대안, 상태 갱신, 다음 사건과 평가 결과를 실제 연결 관계로 표시한다.
- `Decision inputs` 같은 빈 상자에 미정 사항을 숨기지 않는다. 실제 관측값·설정값·추정값과 이들을 사용하는 방법을 구분한다.
- 각 운영 파트의 상세 장은 **핵심 수식 하나를 이해시키는 것**을 목표로 한다. 관련 프레임워크 영역을 앞 장 또는 작은 동일 도식에서 빨간 테두리로 표시한다.
- 원식 인용, 기호 통일, 대상 변경에 따른 수정, 본 연구에서 새로 합성한 식을 구분해 출처를 남긴다. 단위·시간 범위·사건 전환 조건을 확인한다.
- 도식에서는 `Fixed time horizon`처럼 개념을 먼저 쓴다. 수식 장에서 기호를 처음 정의한다. 단순 기호 치환을 수요 예측이나 새로운 최적화 방법이라고 설명하지 않는다.
- 예상 결과는 검증할 비교와 지표를 제시한다. 선행연구 그림은 출처와 함께 **기존 연구의 결과 예시**로 표시하고 본 연구 결과처럼 제시하지 않는다.

## 4. 절제된 디자인과 원문 용어를 유지한다

새 레이아웃·표지·기존 파일 수정을 할 때 [디자인과 파일 검증](references/design-and-delivery.md)을 읽는다. 번역·대본 요청 시에는 [용어와 발표 대본](references/language-and-script.md)을 읽는다.

- 기존 자료의 글꼴·정렬·여백·색상 체계를 유지한다. 회색 보조 문장, 장식적 카드, 중복 소제목을 줄인다. 새 내용을 억지로 끼우기 위해 잘 읽히는 레이아웃을 망가뜨리지 않는다.
- 출처는 본문에 `(Ji et al., 2024)` 정도로 짧게 쓰고, 전체 서지는 번호 없는 References에 모은다. 그림·수식의 출처 위치는 추적 가능하게 남긴다.
- 영어는 원문 논문에서 쓰는 용어와 표현을 우선한다. 비용과 요금, 개인 차량과 공유 차량, 주차와 재배치처럼 의미가 다른 용어를 동의어처럼 섞지 않는다.
- 제목은 가까운 논문의 제목을 참고해 대상·행동·조건을 정확하게 담는다. 콜론은 선택 사항이다. 표지는 실제 학술 발표 표지의 정보 위계를 참고하고 확정 문구를 보존한다.

## 5. 실제 결과물을 읽고 검토한다

1. 내보낸 최종 파일을 렌더링하고 모든 슬라이드를 읽는다. 표·수식·프레임워크는 확대해 확인한다. 텍스트 추출이나 자동 검사만으로 시각 검증을 대신하지 않는다.
2. 다음 명령으로 PPTX의 실제 발표 순서, 텍스트, 관계 오류, 표·수식·그림 개수와 검토 경고를 확인할 수 있다. `python`은 호스트의 Python 3 실행기로 바꿔 쓴다.

   ```bash
   python <skill-dir>/scripts/inspect_pptx.py final.pptx --expect-slides 14 --output private-build/pptx-audit.json
   ```

   `14`는 예시이며 실제 합의한 장수로 바꾼다. 검사기는 글꼴 렌더링, 수식 의미, 논리 타당성, 편집 가능성을 자동 증명하지 않는다.
3. 전체 신규 작성이나 큰 흐름 수정 후 **PPT 전문가 에이전트를 실제로 호출한다.** [독립 검토 브리프](references/design-and-delivery.md#독립-검토)와 최종 자료를 주고, 슬라이드별 피드백을 받은 뒤 필요한 수정을 PPT에 반영한다. 수정본의 해당 장과 앞뒤 연결을 다시 확인한다. 피드백 수령과 수정 전에 검토 완료로 처리하지 않는다. 독립 실행 도구·권한이 없으면 필수 검토가 미실행임을 알리고 자기 검토를 독립 검토로 대체했다고 주장하지 않는다. 작은 문구 수정마다 전체 독립 검토를 반복하지 않는다.
4. 수정 후 영향을 받은 페이지와 앞뒤 연결을 다시 확인한다. 페이지 삽입 시 대본, 페이지 번호, 참조, 프레임워크 강조 위치를 함께 갱신한다.

## 완료 기준

- 가까운 선행연구가 무엇을 밝혔는지, 무엇이 남았는지, 본 연구가 무엇을 검증하는지 구분된다.
- 각 슬라이드가 하나의 설명 역할을 맡고, 주요 수식은 정의·단위·출처와 함께 읽힌다.
- 승인된 사용자 편집과 용어를 보존했고 최종 파일의 렌더를 실제 확인했다. 검증할 수 없었던 부분은 구체적으로 알린다.
- 전체 제작·큰 흐름 수정은 PPT 전문가 에이전트의 실제 피드백을 받았고, 반영한 수정과 남은 쟁점을 작업 기록에 남겼다. 도구 제한으로 미실행한 검토가 있다면 완료로 가장하지 않는다.
- 대본이 있다면 최종 슬라이드의 순서·표현·주장 수준과 일치한다. 발화 시간 추정과 실제 낭독 측정을 구분한다.
- 요청한 결과물만 전달한다. 개인 자료, 원문 PDF, 중간 코드·검사 로그를 불필요하게 배포하지 않는다.
