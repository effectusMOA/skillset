# 디자인과 파일 검증

## 기존 파일이 있을 때

현재 사용자가 지목한 수정본을 먼저 읽고 실제 발표 순서를 확인한다. 물리 파일명 `slide14.xml`이 발표 순서 14번이라는 보장은 없다. 페이지 삽입 뒤 기존 파일을 다시 작업하면 최신 수정분이 사라질 수 있으므로 기준 파일을 명확하게 유지한다.

편집 전에 화면비, 제목/본문/표/수식 글꼴, 색상, 여백, 테두리, 로고, 페이지 번호와 프레임워크 도형을 확인한다. 요청한 범위만 수정한다. 사용자가 직접 바꾼 표지나 로고를 가져오기 쉬운 과거 파일로 덮어쓰지 않는다.

원본이 열려 있어 저장되지 않으면 내용을 지우거나 파일을 강제로 종료하지 않는다. 검증한 별도 수정본을 저장하고 어떤 파일이 최신인지 알린다. 실제로 원본을 교체하지 못했으면 교체했다고 말하지 않는다.

## 정보량과 시각 언어

- 한 장의 설명 역할을 정하고 그 역할과 관계없는 문장을 뺀다. 비교는 표, 제어 흐름은 도식, 결과는 그래프로 보여 준다.
- 사용자 양식을 따르며 제목·본문·표의 위계를 통일한다. 본문이 길어지면 줄이거나 노트로 옮기고 글자를 일괄 축소해 해결하지 않는다.
- 회색 작은 글씨는 필요한 출처·가정에 한정한다. “핵심 인사이트”, “다음 단계”, 제작 메모 같은 중복 안내 문구를 모든 장에 넣지 않는다.
- 장식용 그라데이션, 불필요한 카드, 관계없는 아이콘으로 연구 내용을 감싸지 않는다. 강조색은 실제 구분이나 프레임워크의 현재 설명 위치에 쓴다.
- 표는 읽기 쉬운 소수 열로 정리하고 가능한 한 편집 가능한 표로 만든다. 연구를 여러 임의 분류로 나눠 같은 정보를 반복하지 않는다.

## 표지

표지를 새로 만들거나 사용자가 기계적으로 보인다고 지적하면 실제 관련 분야의 학술 발표 표지 2–3개를 참고해 제목 크기, 행 나눔, 발표자·소속·과목의 정보 위계와 여백을 관찰한다. 템플릿을 그대로 복사하거나 타인의 소속·로고를 차용하지 않는다.

확정 제목, 이름, 학번, 과목은 사용자가 제공한 그대로 쓴다. 요구되지 않은 태그라인이나 연구 요약을 표지에 추가하지 않는다. 긴 제목은 의미 단위로 나누고 장식보다 가독성을 우선한다.

## 수식 렌더링

수식은 가능하면 호스트에서 지원하는 네이티브 수식 기능을 사용한다. 텍스트로 흉내 낸 결합형 악센트는 글꼴·내보내기 과정에서 깨질 수 있다. `hat`, `bar`, 아래첨자, 위첨자, 집합·argmin·양의 부분 연산을 최종 PPTX 렌더에서 확대해 읽는다.

텍스트 추출에 기호가 있다고 실제 화면에서도 보이는 것은 아니다. 반대로 도형으로 보존한 악센트가 텍스트 추출에 없다고 깨졌다고 단정하지 않는다. LaTeX 문자열·미지원 명령·의도하지 않은 대체 글꼴이 화면에 남지 않았는지 본다. 안정성을 위해 이미지나 도형으로 바꿨다면 편집 가능성의 한계를 정확히 알린다.

## 파일 검사와 렌더링

`scripts/inspect_pptx.py`는 Python 표준 라이브러리만 사용하며 입력 파일을 수정하지 않는다. ZIP/관계 무결성, 발표 순서와 슬라이드 텍스트, 표·그림·네이티브 수식 수, 결합 악센트·편집 잠금 등 사람이 볼 항목을 JSON으로 기록한다. 수식이 그림이면 의미나 해상도를 검사하지 못하며, 표·도형이 있다고 편집 준비가 완료된 것도 아니다.

렌더는 호스트에서 이용 가능한 PowerPoint, LibreOffice 또는 발표 도구의 공식 렌더러를 선택한다. 한 방법이 설치되지 않았다면 지원되는 방법을 확인한다. 실패한 렌더를 성공이라고 보고하거나 그림만 있는 이전 버전을 대신 전달하지 않는다.

최종 내보내기 뒤 모든 장을 읽고, 수식·표·지도·도식은 크게 확인한다. 잘린 글자, 겹침, 악센트, 화살표 방향, 그림 범례, 출처, 페이지 번호, 실제 장수와 순서를 확인한다. PowerPoint에서 확인했다고 말하려면 실제로 그 환경에서 확인했어야 한다.

## 독립 검토

전체 PPT 제작 또는 큰 흐름 수정 뒤에는 **실제 PPT 전문가 에이전트를 호출 → 피드백 수령 → PPT 수정 → 수정본 확인**의 순서를 수행한다. 자기 검토만으로 이 절차를 완료했다고 처리하지 않는다. 제작 중 대화를 넘기지 않고 최종 자료와 아래 최소 브리프를 준다. 실제 호스트의 독립 에이전트 기능을 사용하며, 새 사용자 채팅이나 외부 전송을 대신 만들지 않는다.

> 이 연구를 처음 보는 학술 발표 구성 전문가로 검토하세요. 첨부한 최종 PPT와, 있다면 대본만 읽으세요. 연구 내용 자체를 새로 설계하는 것이 목적은 아닙니다. 각 슬라이드의 역할과 앞뒤 연결을 확인하고, 선행연구에서 이미 밝혀진 내용, 남은 한계, 본 연구의 기여가 구분되는지 평가하세요. 프레임워크와 상세 수식의 대응, 처음 설명되지 않는 용어·기호, 정보 과밀, 본문과 대본의 모순도 보세요. 개선이 필요한 위치를 슬라이드 번호와 문제 이유, 최소 수정안으로 제시하고 발표 흐름에 영향이 큰 것부터 정리하세요. 보지 못한 렌더나 접근하지 않은 출처를 검증했다고 하지 마세요.

피드백을 실제로 받은 뒤 근거 있는 중요한 문제를 PPT에 수정하고, 수정한 페이지와 연결 부분을 다시 확인한다. 작업 기록에는 `슬라이드 / 지적 / 반영한 수정 / 미반영 이유 또는 남은 문제`를 간단히 남긴다. 새로운 연구 주장·확정 제목 변경처럼 사용자 선택을 바꾸는 제안은 임의 반영하지 않는다. 전문가가 수정할 문제를 찾지 못했다면 그 판정을 기록하고 억지 수정은 만들지 않는다.

한 차례 검토를 기본으로 하며 중요한 수정에 대한 재확인이 필요할 때만 후속 검토를 요청한다. 검사자에게 원하는 결론이나 과거 지적을 미리 주어 확인 편향을 만들지 않는다. 독립 검토가 불가능할 때도 자료 작성은 가능한 범위에서 진행하되 **필수 전문가 검토 미실행**을 명시한다. 이후 실제 검토 없이 검토 완료를 선언하지 않는다.

## 전달

최신 발표 파일과 요청한 대본만 전달하고 실제 사용에 영향을 주는 제한을 짧게 알린다. 작업 중 검사 로그·임시 이미지·중간 스크립트는 요청하지 않았다면 최종 산출물에 포함하지 않는다. 전체 발표 자료를 스킬 저장소에 예시로 복사하지 않는다. 재사용 가능한 규칙과 실제 연구 자료를 구분한다.
