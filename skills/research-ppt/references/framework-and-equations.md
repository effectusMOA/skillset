# 프레임워크와 수식

## 전체 흐름과 상세 설명의 관계

먼저 연구 유형을 확인한다. 실증 연구는 데이터·처리·추정·검증, 실험 연구는 개입·비교군·관측·평가, 이론 연구는 가정·모형·논증·함의의 관계를 표현할 수 있다. 기존 연구에 없는 시뮬레이터나 사건 전환을 새로 넣지 않는다. 아래 이동·배차·주차 사례는 시뮬레이션·운영 연구에 해당할 때만 적용한다.

사용자가 제공한 도식을 참고할 때 보존할 것은 상자 수나 그림의 외형보다 **주체, 상태, 의사결정, 사건 전환의 관계**다. 대상이 개인 AV에서 SAV로 바뀌면 개인의 귀가 일정과 새 승객 배차처럼 운영 논리가 달라진다. `Home`을 `Depot`으로 이름만 바꿔 같은 모형이라고 설명하지 않는다.

시뮬레이션·운영 연구의 한 장 프레임워크에는 필요한 입력 → 핵심 의사결정 → 행동 대안 → 이동·자원·시간 상태 갱신 → 다음 의사결정/배차 → 성과 평가를 배치한다. 화살표는 실제 제어·정보 흐름을 나타내고 단순 장식으로 쓰지 않는다. 재배치 중 새 배차가 들어오는 경우처럼 전환이 중요한 연구에서는 그 연결을 보여 준다.

상세 장으로 넘어갈 때 전체 도식의 해당 운영 파트를 빨간 사각형으로 표시한다. 동일한 도식을 다시 그리며 위치·명칭·화살표 의미를 바꾸지 않는다. 강조 도식이 본문의 수식을 밀어낼 만큼 커지면, 앞 프레임워크 장에서 다음 파트를 표시하고 상세 장은 간결하게 유지한다.

## 입력과 방법론을 실질적으로 정의하기

입력마다 현재 관측값, 외생 시나리오 값, 모형으로 추정할 값을 구분한다. 선택 규칙은 비용 최소화·규칙 기반·확률 모형·RL 중 실제 채택한 방법을 명시한다. 기본 모형을 구현하기 전부터 여러 고급 기법을 나열해 연구 범위를 넓히지 않는다.

연구 결과를 바꾸는 결정은 명시한다. 예를 들어 결정 시점, 예측 구간, 배차 우선권, 자원 용량, 동시 선택 시 예약 처리, 비용 산정 범위다. 모든 세부 규칙을 슬라이드에 싣는 대신 핵심 가정만 본문에, 나머지는 발표자 노트나 작업 문서에 둔다.

## 한 파트에 핵심 수식 하나

각 장에서 청중이 이해해야 할 질문을 한 문장으로 정하고 이를 답하는 식 하나를 크게 배치한다. 식 아래에는 기호·단위와 해석에 꼭 필요한 항목만 놓는다. 보조 제약식, 유도 과정, 단위 환산의 반복은 노트나 부록으로 옮긴다. 이 원칙은 운영 파트의 설명용 기본값이며, 증명 자체가 목적인 발표에는 맞게 조정한다.

출처를 다루는 방식은 다음과 같이 구분한다.

| 처리 | 필요한 표기 |
|---|---|
| 원식을 그대로 사용 | 저자·연도, 원문 식 번호, 원문 기호 정의 |
| 기호만 통일 | 원식 출처와 `notation adapted`에 해당하는 설명 |
| 대상·대안·비용 항을 변경 | 원식에서 무엇을 바꿨는지, 바뀐 가정 |
| 여러 문헌을 결합해 본 연구 식을 정의 | 각 항의 근거와 `proposed formulation`에 해당하는 설명 |

새로 합성한 식을 특정 논문의 원식 번호로 인용하지 않는다. 반대로 같은 식을 표현만 바꾸고 독자적 모형이라고 주장하지 않는다. 직접 인용 문장은 짧게 유지하고 긴 원문이나 그림을 저장소에 무단 복제하지 않는다.

식 작성 뒤에는 목적함수의 최소/최대 방향, 집합과 인덱스, 추정치와 실측치, 시간·거리·화폐 단위, 양의 부분 연산, 용량·가능 대안 처리를 확인한다. 실제 운영 비용과 선택 시점의 예상 비용을 구분한다.

## 시간 범위와 기호 도입

프레임워크의 입력에는 `H`만 넣지 않고 `Fixed time horizon`처럼 개념 이름을 쓴다. 상세 식에서 처음 `H`를 쓸 때 `time horizon for cost comparison`처럼 역할과 단위를 정의한다. `horizon`만 적어 무엇을 위한 시간인지 남겨 두지 않는다.

고정 평가시간은 가능한 설계 중 하나다. 예측 유휴시간, 실제 유휴시간, 시뮬레이션의 전체 기간과 같은 뜻이 아니다. 수요 예측이 없다면 이를 예측치라고 부르지 않는다. 실제 유휴 종료 사건이 발생하면 평가 가정과 실행 행동이 어떻게 달라지는지 설명한다.

고정 구간을 사용하는 경우 대안들이 같은 시간 구간과 비용 범위로 비교되는지 확인한다. 주차장까지 이동한 뒤 남은 시간에만 주차요금을 적용하는지, 구간 안에 도착하지 못하면 어떻게 처리하는지, 다음 배차가 오면 언제 전환하는지가 일관되어야 한다. 길이에 따라 선택이 달라질 수 있으므로 해당 연구에서는 민감도 분석 대상이 될 수 있다.

이 시간 설계나 기지의 무료 주차 가정은 특정 연구 사례의 선택이지 모든 발표의 기본 모형이 아니다.

## 예상 결과를 정직하게 보여 주기

비교 조건·기준 전략·시나리오·지표를 먼저 정하고 그래프나 지도의 표현을 고른다. 문헌의 지표와 표현 방식을 차용하면 지표 정의·단위·집계 범위를 유지한다. 예를 들어 평균 대기시간과 95백분위 대기시간, 차량당 일일 주차비와 총운영비, 공차 VKT와 전체 VKT는 서로 다르다.

선행연구의 실제 그림을 예시로 쓸 때는 `(Author et al., Year)`와 함께 `Published result — illustration of output format` 또는 자연스러운 같은 뜻의 짧은 문구로 구분한다. 예시는 선행연구의 결과이며 본 연구의 수치 예측이 아니다. 그림 식별 정보·논문·페이지·그림 번호를 노트에 남긴다.

직접 재구성한 도식이나 가상 곡선은 `Schematic illustration`로 표시한다. 시뮬레이션을 실행하지 않았다면 개선율·유의성·우열을 만들어 넣지 않는다. 원자료나 결과 그림을 구할 수 없다면 축과 범례가 있는 빈 출력 설계를 사용할 수 있다.

지도에서는 색·크기·시점·공간 집계 단위를 명확히 한다. 유휴 차량 분포만으로 서비스 형평성 개선을 단정하지 않는다. 지역별 대기시간·요청 충족률처럼 연구 질문에 맞는 추가 지표가 필요하다.
