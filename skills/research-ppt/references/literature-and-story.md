# 선행연구와 논리 구성

## 연구 베이스라인과 도구를 구분하기

가장 최신이거나 코드가 공개됐다는 이유만으로 메인 선행연구를 고르지 않는다. 먼저 **같은 연구 문제를 실제로 분석했는가**를 확인한다. 프레임워크·시뮬레이터 소개 논문은 구현 근거가 될 수 있지만, 운영·정책 연구의 실질적인 비교 대상과 역할이 다르다.

가까운 연구는 연구 대상, 의사결정, 선택 대안, 비용 범위, 제약, 결과 지표가 얼마나 겹치는지로 판별한다. 최신 논문을 찾되, 더 오래된 논문이 가장 직접적인 베이스라인이면 그 이유를 설명한다. 사용자가 SUMO/MATSim처럼 도구를 제한했다면 표에 실제 도구를 확인해 넣는다. 상용 도구나 Python 자체 구현을 이들 시뮬레이터와 같은 것으로 쓰지 않는다.

## 원문에서 확인할 기록

작업용 근거 기록에는 다음을 남긴다. 모든 항목을 슬라이드의 열로 만들 필요는 없다.

- 정확한 제목·저자·연도·저널/학회·DOI 또는 공식 링크.
- 연구 목적과 대상: 개인 AV/SAV, 승객 요청/개인 활동 일정 등.
- 선택 대안·결정 시점·정책 변수·목적함수·비용 단위·자원 제약.
- 방법론, 시뮬레이터와 버전, 사례 지역·네트워크·수요·차량 규모 중 비교에 필요한 항목.
- 실제로 보고한 지표·결과와 한계, 이를 뒷받침하는 절·표·그림·식 번호.
- 코드와 데이터: 공식 저장소/보충자료 공개, 저자 요청 시 제공, 상용 서비스 접근, 확인되지 않음을 구분한다. **시뮬레이터가 공개됐다고 연구 코드·데이터까지 공개된 것은 아니다.**

사용자 제공 PDF도 본문에서 신원을 확인한다. 검색 요약만으로 식이나 세부 운영 규칙을 단정하지 않는다. 전문에 접근하지 못하면 그 범위를 밝히고 주요 차별점 주장을 유보한다.

문헌의 포함·제외 기준은 현재 사용자의 요청과 이어지는 프로젝트 맥락에서 확인한다. 이 스킬의 출발 사례에서는 정식 학회·저널을 중심으로 하고 arXiv 전용 문헌과 MDPI를 비교 대상에서 제외하라는 지시가 있었다. 같은 조건이 확인된 작업에서는 이를 유지하되, 모든 새 연구의 자동 제외 기준으로 확장하지 않는다. 현재 요청에서 다른 기준을 정했다면 그 기준을 적용한다. 인용 수나 저널 명성만으로 방법 적합성을 대신하지 않는다.

## 표는 비교 질문을 중심으로 합친다

기본은 짧은 발표에서 선행연구 1–3장, 비교 표 전체 1–3개다. 중요한 가까운 연구를 분리해 여러 표에 반복하기보다 같은 열에서 비교한다. 두 표가 필요하다면 각 표가 답하는 질문이 달라야 한다. 예를 들어 첫 표는 모형과 선택 대안, 둘째 표는 비용·운영 성과를 비교할 수 있다. 자료가 적다면 한 표면 충분하다.

열을 임의로 창작하기 전에 가까운 원문이나 리뷰 논문의 **실제 선행연구 표**를 확인한다. 작업 기록에 원문 열 제목과 절·표 번호를 남기고 필요한 열을 번역·통합한다. 표가 없거나 전문을 보지 못했다면 그 사실을 밝히고 현재 질문에 맞는 잠정 열을 쓴다. 기존 표에서 가져왔다고 가장하지 않는다.

다음은 후보이며 고정 양식이 아니다.

| 비교 목적 | 사용할 수 있는 열 |
|---|---|
| 의사결정 모형 비교 | Reference · Main contents · Choice alternatives/Parking form · Research method · Key findings |
| 운영·정책 효과 비교 | Reference · Operational strategy · Cost components · Service efficiency · Externalities |

대상 구분이 중요한 연구에는 대상 열을 추가하거나 논문 칸에 간결하게 병기한다. `좋음/부족`, 불명확한 체크 표시, 맥락 없는 `O/X` 대신 실제 모형 요소와 결과를 쓴다. 사용하지 않은 지표는 `미평가`, 확인하지 못한 것은 `확인 불가`로 구분한다.

표 아래 핵심 메시지는 **그 표에서 확립된 지식 하나**다. 예:

> 비용과 활동시간은 개인 AV의 주차 선택을 바꾸며, 공차 이동에도 영향을 준다.

이는 메시지 구성의 예시이지 출처 없이 사용할 연구 결과 문장이 아니다. 실제 선정 문헌의 근거에 맞춰 작성한다. 표의 내용을 읽고도 그 메시지를 도출할 수 없다면 메시지나 표를 고친다.

## 선행연구 설명과 기여점 설명의 역할

선행연구 장에서는 **무엇을 연구했는가 → 어떤 방식으로 분석했는가 → 무엇을 밝혔는가**를 설명한다. 문단 끝마다 “여기서 이 모듈을 가져오겠습니다”를 붙이지 않는다. 방법을 차용한 사실은 연구 필요성의 대체물이 아니다.

다음 종합 장은 세 층으로 만든다.

1. **종합 인사이트:** 여러 가까운 연구를 통해 현재까지 밝혀진 관계.
2. **남은 한계:** 그 관계에서 아직 함께 검증되지 않았거나 특정 조건에만 검증된 부분. 이를 주장할 수 있는 문헌 범위.
3. **본 연구:** 어떤 조건을 변화시키고 무엇을 고정하며, 어떤 선택과 성과의 관계를 추가로 검증할지.

“개인 AV에 세 전략이 있다 → SAV에는 전혀 없다”처럼 대상을 바꿨다는 사실만으로 공백을 만들지 않는다. SAV 주차·재배치 통합 연구가 있으면 먼저 인정하고 비용 기반 선택, 선택 대안의 범위, 배차와 서비스 성과, 정책 실험 중 실제 차이를 좁혀 쓴다.

차별점 문장은 **가장 가까운 기존 연구의 설정 / 이미 검증한 관계 / 우리가 바꾸는 설정 / 새로 확인할 관계**가 이어져야 한다. 범위가 제한된 조사라면 “검토한 연구에서는 …을 함께 평가하지 않았다”라고 쓴다. “최초”, “전무”, “연결한 연구가 없다”는 전면적 주장을 검색 부재로 정당화하지 않는다.

## 제목과 도입부

제목 후보를 요청받으면 가까운 실제 논문 제목 3–5개에서 대상·행동·조건의 표현을 확인하고, 의미가 달라지는 단어를 설명한 뒤 소수 후보를 제시한다. 최신 제목·서지 정보는 공식 출처로 확인한다. 콜론 사용은 유행이라는 추측 대신 내용과 읽기 흐름으로 결정한다. 이미 확정된 제목은 유지한다.

예를 들어 `empty travel costs`, `road tolls`, `parking fees`는 각각 비용 전체, 정책 요금, 주차요금일 수 있어 서로 대체하면 연구 범위가 달라진다. 제목에서는 좁은 정책 실험 하나를 전체 비용 개념과 혼동하지 않는다.

도입부는 실무·정책 문제와 연구 질문을 설명하고, 선행연구 장으로 넘어갈 이유를 만든다. 연구 제안 발표에서 이미 결과를 얻은 것처럼 문제 해결을 선언하지 않는다.
